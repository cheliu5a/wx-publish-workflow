# 正文改写规范

本文件保留原 workflow 中 Step 1.2 的详细要求。主 skill 命中后，只要进入正文改写阶段，就必须遵守本文件。

## 1. 默认叙事结构：故事钩子 + 金字塔骨架

除非用户明确要求新闻快讯、资料索引、纯教程或其他特定体裁，否则公众号文章默认采用“故事钩子 + 金字塔骨架”。

### 故事钩子

位置：标题之后、第一个二级标题之前。

要求：

- 用真实、具体、与主题直接相关的场景、异常、反差、失败经历或观察开篇
- 避免从抽象观点、宏大背景、空泛判断起手
- 技术原理或故障分析类文章优先采用四段式：具体场景 -> 反常结果 -> 风险升级 -> 核心问题
- 钩子必须在 2 到 4 段内自然转到主题
- 不编造第一手经历；没有真实经历时，可从可信观察、常见场景或明确问题切入

示例：

`凌晨两点，你在只有 8GB 内存的机器上执行 malloc(8GB)，调用成功；再申请 9GB 也可能成功。直到程序开始写入，内存压力才集中兑现并触发 OOM。为什么“分配成功”不等于内存已经到手？`

### 金字塔骨架

紧接故事钩子之后，用一段总述说清：

- 本文的核心方法
- 要解决的问题
- 读者最终能获得什么

要求：读者在前 200 字内能回答“这篇文章讲什么方法，我为什么要读”。

## 2. 正文结构要求

文章必须采用“结论先行 -> 分组展开 -> 证据/行动落地”的结构。

硬性要求：

- 导语必须先说清核心方法、解决的问题和最终收获
- 正文大章节必须是核心方法的一级分支，而不是功能堆砌或时间线回放
- 每个二级标题下第一段必须先给本章结论，并用加粗句突出
- 每个章节至少有一个加粗重点句
- 结尾必须用一句加粗总方法回收全文，并给出读者今天能执行的第一步
- 标题层级应能单独构成文章大纲；只读标题、每章首段和加粗句，也应能理解全文方法链

推荐骨架：

```markdown
# 标题

[故事钩子]

[从钩子自然转向主题]

[总述：核心方法 + 方法步骤 + 读者收获]

[一张总览图：方法全景 / 步骤链]

## 一、方法的第一步 / 第一个模块

**这一章要讲的方法是：……**

[案例、机制、表格、操作细节]

**本章重点：……**

## 二、方法的第二步 / 第二个模块

**这一章要讲的方法是：……**

...

**全文方法总结：第一步 -> 第二步 -> 第三步。**

[读者今天就能开始的第一步]
```

## 3. 图文并茂要求

每个一级概念至少配一个可视化元素：

- ASCII 流程图
- Markdown 表格
- 带注释的代码块

优先级：ASCII 流程图 > Markdown 表格 > 代码块注释。

微信不支持 Mermaid，统一改用 ASCII 流程图或表格。

### ASCII 图排版规范（微信代码块）

ASCII 图在微信阅读器中容易因换行导致对齐错乱，必须遵守以下规则：

1. **用标准代码块，不用 `<pre>` 标签**：微信编辑器只可靠渲染 ` ``` ` 代码块，`<pre>` 标签可能被过滤或变形
2. **行宽 ≤ 50 显示列**：微信阅读区宽度约 50–55 个等宽显示列，超过一定会换行，导致边框错位。例如 `┌──────────────────────────────────┐` 不超过 50 格
3. **缩进统一用 2 格**：4 格缩进在窄屏下容易顶到右边界，2 格即可
4. **去掉多余空白行**：ASCII 图内每个空行都占用阅读空间，只保留必要的逻辑分隔
5. **边框文字写在一行**：标注文字（如 `← 文件页`）直接放在边框行右侧，不另起一行
6. **不混用制表符**：ASCII 图必须全部用空格对齐，制表符在等宽字体下宽度不固定
7. **复杂图改用图片**：超过 3 层嵌套或 50 行以上的 ASCII 图，改用 archify 生成图片嵌入
8. **行宽按显示宽度计算，不按字符数**：中文、全角符号、`①②③`、`│`、`─` 等在微信等宽渲染中占 2 格。校验必须用显示宽度（如 `unicodedata.east_asian_width` 中 W/F 计 2），不能只数 `len()`。踩坑记录：一段看起来"38 个字符"的边框实际显示宽度 50+，发布后整图错位
9. **长命令主动折行，不依赖阅读器自动换行**：超过 50 显示列的命令（如 `bpftrace -e '...'`、`echo ... > /sys/kernel/tracing/...`）用 `\` 续行、环境变量缩短路径（`TRACE=/sys/kernel/tracing`）或拆成多行参数。自动换行会顶破代码块边界、破坏 ASCII 对齐
10. **发布后必须校验渲染产物，不能只查源文件**：`feishu-wechat render`（wenyan）会把代码块 `\n` 转 `<br>`、空格转 `&nbsp;`。验收时从渲染 HTML 中提取 `<pre><code>`，还原 `<br>`→换行、`&nbsp;`→空格后重新测量行宽并对照源文件行数；源文件合规但渲染丢换行/串行的情况实际发生过

### 图表密度要求

- 表格数量至少 3 个
- ASCII 流程图或示意图至少 2 个
- 避免连续超过 3 段纯文字；超过就插入图或表格打断

## 4. 段落节奏

- 每段不超过 5 句话
- 重要结论用引用块或加粗单独突出
- 列表用于枚举，表格用于对比，流程图用于表达流程

## 5. 标题层级

- `#`：仅文章标题
- `##`：大章节
- `###`：小节

- [ ] 每个大章节是否至少有一个加粗重点句？
